## Attacked and held

`IOPMAssertionSetProperty` only on success; the `isHeld == held` return is right in all four cases; the release-then-create window on reapply is one IPC round trip at the moment the idle timer has just been reset. `PreventSystemSleep` is deprecated and unsupported in the SDK header, so D3's rejected alternative never existed (noted on D3 for O7). `pmset -g log` shows no powerd-side release of app assertions across today's sleeps, so the wake re-apply is belt and braces. The policy is a reducer over current inputs, so any ordering of the wake message against the dock's re-enumeration converges. Every (`hold`, `before`, `reapply`, create-ok) combination of the logging rule was enumerated: `hold.off` is never logged with nothing held. Launch takes the hold at +160 ms through the priming pass. ⌘K is inert while the menu is closed. Release on undock is synchronous in one callback with a single `write(2)` ahead of it. Nothing claims control the API does not give; no polling; DockCore is AppKit-free.
