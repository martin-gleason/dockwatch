# Review — F5 installable app and launch at login

Created: 2026-10-18 14:55 -05:00 · Edited: 2026-10-18 14:55 -05:00

**Reviewed:** commits `7b588db` and `c864e0b` on `F5/bundle`, by the adversarial reviewer in a fresh context, 2026-10-18, with the dock unplugged and the Mac on battery throughout. **Verdict: may merge once findings 1 and 2 land.** Two majors, four minors. The bundle, signature, sandbox entitlement, Open Log in the container and the Launch at Login toggle were all seen working from the installed app.

## What the reviewer ran

The build script, `codesign` verify and entitlements, `spctl` (rejected, as expected for ad-hoc), `plutil` on both plists, the icns unpacked (all ten sizes), `swift test`, the installed app under a `log stream` with its menu driven through System Events, the bare release binary, and **two ad-hoc signed, sandboxed probe executables** carrying the app's entitlements that call the same APIs the app calls, run plain and sandboxed side by side against a throwaway disk image. That last method is what answered RR12 without the dock. One tool caveat: `sfltool dumpbtm` hung on later calls, so the final login-item state was read from the menu's checkmark, not the tool.

## Findings and what was done

| # | Severity | Finding | Disposition |
|---|---|---|---|
| 1 | major | **App Sandbox denies the blocker lookup.** The sandboxed probe got `EPERM` from `proc_listpidspath`; the sandbox profile denies `process-info*` except pid-info. So every busy eject from the installed app read "In use by a system process", even for a file the owner's own Terminal holds. The same probes **proved** that IOKit USB notifications and registry reads, the IOMedia parent walk, `IOPMAssertionCreateWithName`, `IORegisterForSystemPower`, `DASessionCreate` + `DADiskUnmount` (a real unmount succeeded), `SMAppService` and Open Log on the container path all work inside the sandbox. | **Code made honest**: a refused lookup is its own result, "In use by another process; the sandbox cannot say which", distinct from "a system process" (lookup ran, holder is root). **D25 proposed** for the owner: accept this under the sandbox for MVP, or name holders in v1.5 outside the sandbox. RR12 rewritten with the probe results; A1 shrunk to the dock-only checks. |
| 2 | major | D24 moved the log into the container but O13's overnight command still read the old file, so the experiment run from the installed app would have windowed from a stale afternoon timestamp. Confirmed by running the command as written. | **O13 rewritten** to the container path and to say "the file Open Log reveals". |
| 3 | minor | "Greyed out when not running from a bundle" was false: `NSMenu.autoenablesItems` re-enabled the item on every open because its target answers the action. Confirmed on the bare binary. | **Fixed**: `autoenablesItems = false`; verified: `launch=false keep=true open=true` on the bare binary. |
| 4 | minor | The flat icns renders as macOS 26's legacy fallback: a grey tile with the ring inset at about 55 percent. HueBar's script compiles an Icon Composer `.icon` edge to edge. | **Recorded as D26 (proposed)**: the Finder icon moves to an Icon Composer document in F7, the icon feature, where the ring is drawn anyway. |
| 5 | minor | The plan's Design was rewritten in place after the gate again, and the gate commit's message did not match its content. | **A "Design changes after the gate" section added** to the F5 plan; the gate commit is left as it is in history and named here. |
| 6 | minor | Evidence and wording: two of the four sandbox checks were runnable on a disk image and were recorded as "not yet possible"; `Info.plist`'s stamp was stale; the login-launch itself (log out and in) is unproven. | Evidence table and status line corrected; stamp updated; the login launch stays with the owner. |

Also from the review, and left as is: the M9 mutation had silently "escaped" because its row named the test class before it was renamed; `mutate.sh` now refuses a filter that runs no test, and M9 is re-run and killed.
