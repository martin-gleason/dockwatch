## Findings and what was done

| # | Severity | Finding | Disposition |

| 1 | major | A FIFO at the log path blocked `open` before `fstat` could refuse it; the app's first `tail` at launch never returned (`timedOut` on both `tail` and `append` at 3 s). | **Fixed**: `O_NONBLOCK` on every open; a regular file ignores it, a FIFO returns at once and is refused. | 2 | major | T5's checkpoint said "displays with those characters removed" but `plain` had one call site: volume names reached the Dock Volumes rows, the eject result title and the loss notification body raw. | **Fixed** at the models, not the call sites: `EjectMenuModel` makes titles plain on record and on rows, `LossCoalescer.add` makes names plain; tested with a U+202E name in each. |
| 3 | minor | The fresh-line probe opened the path a second time, so a file swapped between the two opens gave the probe another file's last byte; ~12 µs per append. | **Fixed**: one descriptor, `O_RDWR \| O_APPEND`, `pread` on it. |
| 4 | minor | A dangling symlink at the previous-file path made every rotation fail ("already exists"), so the cap NFR6 promises would never hold again. | **Fixed**: the previous file is removed unconditionally (`removeItem` does not follow links); tested. |
| 5 | minor | `O_NOFOLLOW` does nothing for a hard link and nothing said so. | **Recorded**: in `openRegularFile`, the plan and the security review: same user only, out of scope. |
