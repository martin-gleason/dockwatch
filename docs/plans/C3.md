# C3 — Security hardening from the black-hat review

Created: 2026-10-18 18:58 -05:00 · Edited: 2026-10-18 18:58 -05:00

**Status:** open (awaiting the owner's yes, O20) · **Priority:** P1 · **Owner:** agent · **Milestone:** MVP

Not a feature: nothing a user notices when it works. Six small changes from `docs/reviews/security-2026-10-18.md`, each a behaviour the app already promises, made harder to break. Nothing here changes FR1–FR9; the two findings that would (dock identity by topology, Developer ID signing) are D31 and D30 for v1.5 and are not built here.

### C3-T1 — The log is a regular file the app opened itself

Owner: agent · Checkpoint: a symlink or a directory at the log path makes `append` fail with a named error and `tail` return nothing, never a write through the link.

`EventStore.write` opens with `O_NOFOLLOW`; `tail` and `write` refuse anything `fstat` says is not a regular file. Mutation M15: remove `O_NOFOLLOW`; the symlink test must catch it.

### C3-T2 — Tail trimming cannot blank the menu seed

Owner: agent · Checkpoint: a file whose final 512 KB holds one unterminated line still yields the events before it; a window that starts at a line boundary loses nothing.

Drop the first slice of the window only when more than one line survived and the slice does not decode. In the same pass, `EjectMenuModel.rows` never decorates a mounted row with a done result. Mutation M16: restore the unconditional `removeFirst`; the single-line test must catch it.

### C3-T3 — The remembered dock controller is forgotten when nothing remains on it

Owner: agent · Checkpoint: the 18-line recorded pull still counts 18 of 18 (F4b), and after the last child on the dock's controller terminates, `isOnDock` answers false for that controller.

`DockTracker.apply` clears `lastKnownDockLocationID` when `present` holds no device on that controller byte. Mutation M17: never clear; the new test must catch it.

### C3-T4 — The secret scan catches what it missed, and runs in CI

Owner: agent · Checkpoint: a staged file of fakes (PKCS#8 and PGP headers, `github_pat_`, `gho_`, `sk-ant-`, `sk-proj-`, `AIza…`, a JWT, a Slack webhook, an `AKIA…` inside a binary blob) is refused by the hook and by the CI job; the real tree passes.

One pattern file read by both `.githooks/pre-commit` and a CI step; `git diff --cached --binary` or `git show` per staged blob so binaries are scanned. Proven by breaking: the fakes are committed to a scratch clone, never here.

### C3-T5 — Device names are plain text before they are logged or shown

Owner: agent · Checkpoint: a subject containing NUL, U+202E, U+200B and a C0 control logs and displays with those characters removed; ordinary Unicode names (accents, CJK) pass unchanged.

One `sanitized` on the string used for `subject` and `detail` values in DockCore, applied where events are made, so the log and every menu line share it. Mutation M18: return the input unchanged; the test must catch it.

### C3-T6 — CI pinned and least-privilege

Owner: agent · Checkpoint: `ci.yml` names `actions/checkout` by commit SHA with the tag in a comment, declares `permissions: contents: read`, and the run on this branch is green.

## Order

T1, T2, T3, T5 are DockCore changes with tests and can go in one commit each; T4 and T6 touch the harness and CI. Serial, as before.
