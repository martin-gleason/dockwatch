Not a feature: nothing a user notices. Until it exists every later claim in this project is an assertion. The contract is five capabilities; the Swift shape is `swift test`, a count parsed from its output, a floor file, a mutation script and a pre-commit hook.

### C1-T1 — Package skeleton builds and tests green

Owner: agent · Checkpoint: `swift test` exits 0 on an empty suite.

### C1-T2 — Assertion count and floor

Owner: agent · `scripts/count_assertions.sh` prints one integer parsed from `Executed N tests`; `Tests/ASSERTION_FLOOR` holds it. Checkpoint: the integer matches the `swift test` summary line.

### C1-T3 — Pre-commit and commit-msg hooks

Owner: agent · `.githooks/pre-commit` runs `swift test`, the floor, and `gen_status.py --check`; `.githooks/commit-msg` rejects a register ID in the subject; `git config core.hooksPath .githooks`. Checkpoint: a commit with `D1` in its subject is refused, and a floor set one higher than the count refuses the commit. These are the proofs-by-breaking.

### C1-T4 — Mutation script

Owner: agent · `scripts/mutate.sh M1` applies the named break, shows the catching test red, restores the tree. Checkpoint: red output in the terminal, `git status` clean afterwards.

### C1-T5 — Declare and verify the harness

Owner: agent · Declaration is already in `docs/conventions-local.md`. Checkpoint: `python3 ~/Local_Dev_Projects/turing-review/scripts/check_harness.py --run ~/Local_Dev_Projects/dockwatch` reports `ok`.

### C1-T6 — CI and branch protection

Owner: human for the push and the setting, agent for the workflow file · GitHub Actions on macOS running `swift build` and `swift test`; branch protection PR + CI + rebase-merge. Checkpoint: a red test blocks a PR. Depends on `O6`; not part of today's work.
