# F6 — Eject dock volumes

Created: 2026-10-18 12:05 -05:00 · Edited: 2026-10-18 13:02 -05:00

**Status:** in progress (gate crossed 2026-10-18, "you can begin f6") · **Milestone:** MVP · **Owner:** agent · **Delivers:** FR9 (added by D11)

Order per D19: after F3, before F5 and F4. Learning level 5% (D6); every task is `owner: agent`.

## What the user gets

Every mounted volume on a disk that hangs off the dock appears in the menu with an Eject item, plus one "Eject all dock volumes". Each eject either happens or the menu says what blocked it ("Backups: in use by backupd"). Pulling the dock's cable after "Eject all" succeeds is then safe for the drives.

## What it cannot do, said plainly

macOS has no API to "eject" a keyboard, a receiver, a tracker or any device without storage. For those, "remove" is what the log already records: the device is gone and the menu no longer lists it. The menu never offers an action it cannot perform (CLAUDE.md non-negotiable).

## Design

- `VolumeEjector` (DockCore, DiskArbitration): `DADiskUnmount` with `kDADiskUnmountOptionDefault` (never force), completion callback carries a `DADissenter`; the dissenter's status and PID are mapped to a process name via `proc_name` so the menu can say who. Result type `EjectResult { done | blocked(by: String) | failed(status) }`.
- "On the dock" classification (DockCore, pure, tested): a disk is on the dock when the IOUSB location ID of its USB device shares the controller byte (`locationID >> 24`) with the dock device's location. On this Mac the dock is `0x02148000` and its drives enumerate under the same `AppleT6000USBXHCI@02000000`; the built-in ports are controllers 0 and 1. The locations come from the disk's `DADiskDescriptionDevicePathKey` / IOMedia parent chain, read by `VolumeMonitor` (F2) and stored on the `volume.mounted` event, so F6 depends on F2.
- `EjectMenu` (DockWatch): one item per dock volume, "Eject all dock volumes", rebuilt on open. Results appear as the item's subtitle for 10 seconds and in the log as `volume.eject` events (FR3 gains a kind; recorded as a `D<n>` if the owner wants it in the spec).

## Tasks

T1 and T2 independent; T3 depends on both and on F2. Run serially, by the same decision as F2 and F3.

### F6-T1 — VolumeEjector with dissenter mapping

Owner: agent · Delivers the FR9 mechanism · Checkpoint: ejecting "Down Under" while `tail -f "/Volumes/Down Under/x"` runs returns `blocked(by: "tail")`; without it returns `done` and the volume is gone from `mount`.

### F6-T2 — Dock classification

Owner: agent · Delivers nothing user-visible (foundational) · Checkpoint: tests show a disk at `0x02240000`-rooted location is on the dock, one at `0x01100000` is not, and the rule is expressed only in terms of location IDs (M7).

### F6-T3 — Menu items and results

Owner: agent · Delivers FR9 · Checkpoint: the menu lists the four dock volumes with Eject; "Eject all" unmounts all four; a blocked one names the process.
