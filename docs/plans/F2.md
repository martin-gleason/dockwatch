# F2 — The event log

Created: 2026-10-18 10:55 -05:00 · Edited: 2026-10-18 11:59 -05:00

**Status:** in progress (gate crossed 2026-10-18, "start f2") · **Milestone:** MVP · **Owner:** agent · **Delivers:** FR3, FR8

Learning level 5% (D6); every task is `owner: agent`.

## What the user gets

A file at `~/Library/Logs/DockWatch/events.jsonl` that explains the next drop: which device went, which volume, whether the Mac was asleep, what the charger was doing. "Open log" in the menu reveals it.

## Design

- `Event` (DockCore, pure, `Codable`): `{ts, kind, subject, detail}` where `kind` is one of `usb.attached usb.detached volume.mounted volume.unmounted volume.disappeared system.sleep system.darkwake system.wake power.connected power.disconnected`. `detail` carries vendor/product/location for USB, the BSD name and whether the unmount was clean for volumes, watts for power.
- `EventStore` (DockCore): appends one JSON line per event with `O_APPEND`; rotates to `events.1.jsonl` at 20 MB (NFR6). A write failure is recorded in memory and exposed as `lastError` for the menu; it never throws into the UI.
- Sources, all DockCore, all callback-driven (NFR2):
  - `USBMonitor` from F1, now forwarding every device, not just the dock.
  - `VolumeMonitor`: DiskArbitration `DARegisterDiskAppearedCallback`, `DARegisterDiskDisappearedCallback`, `DARegisterDiskDescriptionChangedCallback` on the volume-path key, with the session scheduled on the main run loop. A disk that disappears while mounted is `volume.disappeared`; a description change that drops the volume path is `volume.unmounted`.
  - `SleepMonitor`: `IORegisterForSystemPower` with `kIOMessageSystemWillSleep`, `kIOMessageSystemHasPoweredOn`, and `kIOMessageSystemWillPowerOn`; full wakes only (`system.wake`): a dark wake delivers no legacy-app message, see D18. Always acknowledges sleep with `IOAllowPowerChange` so it never delays sleep (NFR8).
  - `PowerMonitor`: `IOPSNotificationCreateRunLoopSource`; on change reads `IOPSCopyExternalPowerAdapterDetails` for watts and the power source state for connected/disconnected. Emits only on transitions, not on every battery-percentage tick.
- `OpenLogAction` (DockWatch): `NSWorkspace.shared.activateFileViewerSelecting`.

## Tasks

T1 first; T2, T3, T4 are independent. **Run serially, by decision at the gate:** the Workflow tool requires an opt-in the harness recognises (the owner typing `ultracode`), and the agent does not infer one from CLAUDE.md prose. Each task is small enough that the fan-out would cost more than it saves.

Owner: agent · Delivers nothing user-visible (foundational) · Checkpoint: tests show append preserves prior lines (M3) and rotation at the threshold keeps exactly one previous file.

### F2-T2 — VolumeMonitor

Owner: agent · Delivers FR3 volumes · Checkpoint: eject "Down Under" from Finder produces a `volume.unmounted` line; pulling a drive's USB cable produces `volume.disappeared`.

Owner: agent · Delivers FR3 sleep, wake, power · Checkpoint: close the lid for a minute and see `system.sleep` then `system.wake`; unplug the charger and see `power.disconnected` with the last watts.

Owner: agent · Delivers FR3 USB, FR8 · Checkpoint: unplug the keyboard and see `usb.detached` naming "Das Keyboard"; the menu item reveals the file in Finder.

**Decision taken while building, then overturned by the review.** The plan named `IOPMGetCapabilitiesDescription` for telling dark wake from wake; it is private API, so NFR1 forbids it. The build substituted a display-asleep heuristic; the review showed from xnu's source that a dark wake never reaches this app at all, so the heuristic could only mislabel full wakes. The kind is gone and D18 records why. Review: `docs/reviews/F2.md`.
