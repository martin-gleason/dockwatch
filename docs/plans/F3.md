# F3 — Keep the dock awake

Created: 2026-10-18 10:55 -05:00 · Edited: 2026-10-18 11:15 -05:00

**Status:** planned, awaiting the gate · **Milestone:** MVP · **Owner:** agent · **Delivers:** FR5, and the third state of FR1

Learning level 5% proposed (`O2`); every task is `owner: agent`.

## What the user gets

A "Keep dock awake" item in the menu. While it is checked and the dock is plugged in, the Mac does not idle-sleep, so the power-delivery loop that drops devices never starts. The display still sleeps. Pull the dock and the hold is gone within five seconds; the Mac behaves exactly as before.

## Design

- `HoldPolicy` (DockCore, pure): a function `(toggle: Bool, docked: Bool) -> Bool` plus a tiny reducer over the inputs `toggleChanged`, `dockChanged`, `didWake`. It owns no IOKit. Every branch is tested (M1, M2, M6).
- `AssertionController` (DockCore, IOPMLib): creates `kIOPMAssertionTypePreventUserIdleSystemSleep` named `"DockWatch: keeping the Thunderbolt dock awake"` with `IOPMAssertionCreateWithName`, releases with `IOPMAssertionRelease`. Idempotent: `set(held: Bool)`. This type leaves display sleep untouched and dies with the process, which is why it was chosen over `pmset` or a `PreventSystemSleep` assertion (D3).
- Re-evaluation on `system.wake` and `system.darkwake` from F2's `SleepMonitor` (NFR8): macOS may release assertions across some sleep transitions; the controller re-applies the policy's answer on every wake.
- Persistence: the toggle lives in `UserDefaults` under `keepDockAwake`; default **off** (D10).
- `StatusItemController` gains the third icon state (held) from `AssertionController.isHeld`.

Owner: agent · Delivers nothing user-visible (foundational) · Checkpoint: tests show undock releases (M1), toggle off never holds (M2), wake while docked and on re-asserts (M6).

### F3-T2 — AssertionController

Owner: agent · Delivers the FR5 mechanism · Checkpoint: `pmset -g assertions` lists the DockWatch assertion after `set(held: true)` and not after `set(held: false)`.

### F3-T3 — Menu toggle, persistence, wiring, held icon

Owner: agent · Delivers FR5 and FR1's third state · Checkpoint: toggle on while docked and the assertion is present within 1 s; pull the dock and it is gone within 5 s; relaunch and the toggle is still on.

## Risks touched

RR1 (an idle-sleep assertion does not stop lid-close sleep on battery without an external display, nor an explicit Sleep command; the menu wording says "idle sleep"), RR2 (a Mac held awake around the clock), RR4 (the hypothesis could be wrong; the evidence row above is the test).
